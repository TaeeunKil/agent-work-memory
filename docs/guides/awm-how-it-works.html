AGENT WORK MEMORY / PROJECT GUIDE

대화를 모으고,
다시 꺼내 쓸 작업 기억으로.

AWM은 로컬 대화 기록을 수집하고, 허용된 AI 정리를 거쳐 개인 Wiki와 근거 기록으로 남기는 도구다.

2026.11.10 코드 기준 · 동작 설명서 · 실시간 상태판 아님

수집

새 대화와 추가된 내용을 근거로 보관한다.이 단계는 AI를 호출하지 않는다. 수집 성공만으로 Wiki 정리까지 끝난 것은 아니다.

정리

대화 근거와 기존 Wiki를 읽고 프로젝트·결정·문제 해결 지식을 갱신한다.유효한 권한이 필요하다. 실패하거나 권한이 만료되면 정리할 내용은 대기 상태로 남는다.

업로드

Vault의 변경된 Markdown을 Git 저장소에 올린다.최근 커밋이 있다는 사실만으로 최신 대화가 모두 정리됐다고 판단할 수 없다.

DISCOVERY

새 기록은 세션 저장 위치를 다시 훑어서 찾는다.

조사하면서 질문하거나 도구를 실행하면, 대화 앱이 그 내용을 자신의 기록에 저장한다. 다음 AWM 수집이 이 파일을 찾아 이전 수집 위치와 비교한다. 화면의 대화 목록 순서나 “최근 대화” 표시를 감시하는 방식은 아니다.

대표적인 입력 위치

Codex
~/.codex/sessions/**/*.jsonl
~/.codex/archived_sessions/**/*.jsonl

Claude
~/.claude/projects/**/*.jsonl

Cursor
전용 수집기가 로컬 기록 저장소를 읽음

추적하는 정보

각 AWM 세션마다 마지막 처리 줄, 파일 크기, 정규화기 버전 등을 보관한다. Codex는 중복 정규화를 위해 앞부분 일부를 겹쳐 확인하며, 이미 저장한 이벤트는 다시 넣지 않는다.

파일이 줄어들거나 파서 버전이 달라지면 다시 읽어 재구성한다. 단순히 “마지막 바이트 뒤만 읽는다”는 구현은 아니다.

CONTINUATION

예전 대화를 이어 쓰면, 같은 기억에 새 내용이 붙는다.

같은 세션 기록에 이어 쓴 경우 기존 AWM 세션을 갱신한다. 실제로 새 이벤트가 저장되면 내용 개정 번호가 올라가고, 마지막 Wiki 정리 때의 개정보다 최신이면 다시 정리할 대상으로 잡힌다.

최신 목록에도 올라오나?

수집 후 반영된 파일 수정 시각으로 세션 목록을 정렬하므로, 이어 쓴 대화는 최신 쪽에 나타난다. 수집 전까지 즉시 반영되는 실시간 감시는 아니다.

같은 ID면 무조건 합치나?

아니다. 제공자 ID가 같아도 서로 다른 기록 파일이면 별도 이력으로 보존한다. 파일이 보관 폴더로 이동한 경우는 기존 경로의 소실과 후보의 유일성을 확인해 기존 세션을 연결한다.

중복·이동·동시 변경은 어떻게 다루나?
  • 수집 위치는 제공자 ID가 아니라 AWM 내부 세션별로 관리한다.
  • 같은 rollout 파일이 활성 폴더와 보관 폴더에 함께 있으면 활성 사본을 우선한다.
  • 이벤트 식별자로 이미 저장한 메시지·도구 결과의 중복 삽입을 막는다.
  • 수집·정리·게시 작업은 잠금으로 충돌을 조정한다.
  • 정리 중 생긴 새 개정을 이미 정리된 것으로 덮어쓰지 않는다.

DATA BOUNDARY

대화 근거는 DB에, 오래 쓸 지식은 Markdown에.

로컬 실행 상태

%LOCALAPPDATA%\AgentWorkMemory

agentworkmemory.db
  세션 · 메시지 · 도구 기록
  수집 위치 · 개정 번호
  작업 결과 · 검색 인덱스

설정 · 로그 · 정리 작업 공간

실행 상태 DB는 Markdown Vault에 넣지 않는다.

개인 Vault

Documents\AgentWorkMemoryVault

Home.md
inbox/agent-sessions/  대화 근거
projects/             프로젝트
decisions/            결정
problems/             문제와 해결
procedures/           작업 절차
systems/              시스템 지식
unfinished/           미완료 작업
imports/              가져온 자료
“파일은 안 모으지?”에 대한 정확한 답

프로젝트의 코드·문서 폴더를 통째로 복사하는 방식은 아니다. 다만 대화 로그에 남은 도구 호출과 결과도 수집하므로, 도구로 읽거나 출력한 파일 내용은 대화 근거에 포함될 수 있다.

정리는 별도 작업 공간에서 진행하고 결과를 검증한 뒤 Vault에 적용한다. 원격 정리에는 명시적인 콘텐츠 전송 허용이 필요하며, 로컬 모델을 선택하는 경로도 있다.

OPERATIONS

수집 시각과 정리 결과를 따로 확인한다.

awm serve로 뷰어를 시작한 뒤 127.0.0.1:3928에 접속한다. 뷰어는 이 컴퓨터의 루프백 주소에서 제공된다.

화면확인할 내용
Today현재 상태와 필요한 다음 작업
Sessions수집한 대화, 최신 내용, 정리 여부
Knowledge정리된 Wiki와 연결된 근거
Activity실행 이력, 성공·실패와 이유

상태 확인

awm auto status
awm auto-distill status
awm vault status

수집 예약, 정리 권한·예약, Vault 게시 상태를 각각 확인한다.

수동 처리 예시

awm sync --include-content

awm distill --pending --limit 1 --using codex --allow-remote-content

두 번째 명령은 대기 세션 1개를 Codex 런타임으로 정리하며, 선택한 대화 내용의 원격 전달을 허용한다.

어디까지 처리됐는지는 세 가지로 읽는다.

최근 수집이 성공했는가 → 추가된 개정이 정리됐는가 → Vault 변경이 업로드됐는가. 권한 만료나 DB 오류가 있으면 어느 단계에서 멈췄는지 Activity와 각 상태에서 확인한다.

코드를 읽을 때의 구조

app.py가 구성 요소를 연결한다. CLI와 뷰어는 진입점, workflows는 작업 순서 조정, services는 제품 동작, stores는 저장, integrations는 Codex·Claude·Cursor 등의 외부 형식을 담당한다. 현재 제품 코드는 src/agentworkmemory/이며 src/codealmanac/는 과거 참조 코드다.
